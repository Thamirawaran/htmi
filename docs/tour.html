HTMi · a tour

Review your agent's pages on the page itself

Coding agents now explain their work as HTML pages: a diagram of the change, charts, a review guide. HTMi lets you comment on the exact element you mean, hands your agent that one comment with the context it needs, and keeps the comment on its element through the agent's edits, or tells you plainly that it can't.

  • Open source, MIT
  • No account, no server
  • Hermes Agent, Claude Code, Codex, GitHub, VS Code

Feedback in chat does not point at anything

A page has three charts. "The second chart looks off" leaves the agent to guess which chart and what is wrong, and after the next edit nobody knows whether the remark still applies. With HTMi the comment sits on the chart itself.

The review loop

You and your agent take turns on the same page. Each comment goes to the agent with its target, and each edit comes back as a reply on that comment.

What happens to a comment after an edit

A comment keeps its target's id, a digest of the target's content and the version you saw. When the page changes, HTMi looks the target up again and reports one of five results. It never moves a comment to a guess: a likely match is shown for a person to confirm, and agents have no tool to reattach a comment.

What your agent gets, and what it may do

One comment, with its context

  • the target and its neighbours
  • constraints the page declares
  • the prose around it
  • the thread, word for word
  • what the source does not say
  • what was left out, with the command to fetch it

Checked edits, and limits

  • An edit names its target and the content it expects there. If that content changed, nothing is written.
  • If anything outside the target would change, the edit is refused.
  • Comment text reaches the agent as data, never as instructions.
  • Agents reply and mark comments addressed. Resolving and reattaching are left to people.

Where it runs

The same comments and the same checked edits, in the tools you already use. Documents can be HTML pages, Markdown with Mermaid diagrams, or GitHub issue and pull request descriptions.

What it does on your computer

  • No account, no server, no telemetry. Comments are a file in your repository (.htmi/annotations.jsonl) or ordinary GitHub comments.
  • It reads and writes only inside the repository; a path or symbolic link that leads out is refused.
  • GitHub work goes through your own gh login. The Chrome extension posts nothing itself: you press Comment.

Comment on this page

This page is an HTMi document. If you are reading it on GitHub with the HTMi extension, click any part of it, a figure, a table row or a sentence, and write what you think.

Then type an issue number under the preview and choose Open it with the comments. Your comment lands in that issue's comment box, pinned to what you clicked, and nothing is posted until you press Comment.

Without the extension, GitHub shows this file as HTML source; the README has a picture of it.
